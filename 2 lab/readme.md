# Лабораторная работа 2 — продолжение финансового ассистента

Финансовый ассистент из **первой лабораторной** перенесён на LangChain и дополнен
файловой памятью фактов. Он помнит имя, сумму и валюту сбережений, финансовую цель,
предпочитаемый банк, страну и срок накопления. После перезапуска эти сведения
используются в расчётах без повторного опроса.

## Преемственность с первой лабораторной

`fact_agent.py` напрямую импортирует `../1 lab/finance_agent.py`:

- все шесть функций: время, курс валюты, вклад, ключевая ставка, инфляция, налог;
- `find_call()` и `call_function()` — существующий разбор и выполнение текстовых вызовов;
- промпты `chat`, `v1`, `v2`, `v3` и ограничение `MAX_STEPS`.

Функции и данные не дублируются. Сохранён текстовый протокол `<|call|>...<|call|>`
без native tools/function calling/MCP. Вариант `chat` оставлен как базовый режим
сравнения из первой работы; для работы с инструментами используйте `v2` или `v3`.
По результатам первой лабораторной по умолчанию выбран `v2` для локальных моделей;
для эталонной облачной конфигурации можно выбрать `v3` через `LLM_PROMPT`.

| Было в lab 1 | Добавлено в lab 2 |
|---|---|
| Прямой вызов OpenAI-клиента | LangChain LCEL: prompt → model → parser |
| История в оперативной памяти | Отдельные факты в JSON по `user_id` |
| Нет извлечения профиля | Отдельный LLM-запрос со structured JSON output |
| После выхода профиль теряется | Загрузка файла при старте |
| Вызовы печатаются в основной консоли | Отдельная служебная CELL в notebook |

## Настройка настоящей модели

Используйте llama-server или OpenRouter, настроенные в первой лабораторной.

```powershell
notepad '.\2 lab\.env'
```

| Переменная | Значение |
|---|---|
| `LLM_BASE_URL` | Адрес API из lab 1, например `http://127.0.0.1:8080/v1` |
| `LLM_API_KEY` | `none` для локального сервера или собственный ключ |
| `LLM_MODEL` | Точный ID вашей модели |
| `LLM_PROMPT` | `v2` по умолчанию; также `chat`, `v1`, `v3` |
| `LLM_STRUCTURED_METHOD` | `json_mode` или `json_schema`, если сервер поддерживает его |

Сохраните в файле строки вида `LLM_MODEL=идентификатор-модели`, подставив
значения для своего сервера.

Установите `RUN_LIVE = True` и свой `USER_ID`, выполните notebook по порядку.
Рабочая память создаётся в `memory.local.json`. `.env` и рабочая память исключены
из Git. `/exit` завершает сессию. **Restart Kernel → Run All** загрузит факты снова.

Пример: сообщите «Я Анна, у меня 1000 долларов, хочу накопить финансовую подушку,
предпочитаю ВТБ». Перезапустите kernel и спросите «Сколько моих сбережений получится
в рублях?». Ассистент получает сумму и валюту из памяти, вызывает исходную функцию
курса и использует её результат. В чате виден ответ, в служебной CELL — вызов и результат.

## Архитектура

### Окно диалога, суммаризация и ветвление

Агент передаёт модели три последние завершённые пары вопрос–ответ дословно.
При вытеснении пары `DialogueContext` добавляет в сводку тему вопроса (до 120
символов) и первое предложение ответа (до 220 символов). Это экстрактивная
суммаризация. В сводке остаются четыре последние выдержки. Окно и сводка
живут до конца сессии, профиль загружается с диска при следующем запуске.

Команда `/remember {"level":"beginner","goal":"накопить подушку"}` передаёт
параметры компоненту `FactMemory.remember_json`. Он разбирает JSON, проверяет
поля по схеме `Facts` и объединяет их с профилем пользователя. Ошибочный ввод
возвращает подсказку. Команда работает без обращения к модели.

Для каждого обычного вопроса `teaching_mode` выбирает инструкцию по сохранённому
уровню. Для `beginner` модель получает задание разобрать простой пример по шагам,
для `advanced` — привести формулу, допущения и ограничения. Для среднего или
неизвестного уровня используется обычное объяснение. Сравнить инструкции и
увидеть вытеснение реплик можно в разделе «Окно, сводка и выбор сложности» ноутбука.

### Обработка сообщения

1. `FactMemory` читает и проверяет JSON, выбирает профиль пользователя.
2. `EXTRACTION_PROMPT | model.with_structured_output(Facts)` извлекает явно
   сообщённые факты. «У меня 1000 долларов» — факт, «Сколько рублей в 250 долларах?»
   — расчётный вопрос, из которого не следует, что пользователь владеет этой суммой.
3. Факты проходят Pydantic-валидацию и сохраняются через временный файл и `os.replace`.
   Новые значения исправляют старые; `null` не стирает известные сведения.
4. Финансовый промпт lab 1 дополняется профилем. LCEL-цепочка выдаёт текстовый вызов.
5. Исходные `find_call`/`call_function` выполняют его; результат возвращается модели.
   Цикл продолжается до финального ответа, максимум шесть вызовов функций.
6. JSON содержит только факты, без истории, курсов, ставок и результатов инструментов.

## Проверка

```powershell
.\.venv\Scripts\python.exe '.\2 lab\demo_restart.py'
.\.venv\Scripts\python.exe -m unittest discover -s '.\2 lab' -v
```

В демонстрации первый процесс сохраняет профиль и завершается. Второй восстанавливает
его и действительно выполняет `get_exchange_rate(USD)` из lab 1. По учебному курсу
92.50 получается 92 500 рублей за 1000 USD. Итоговая память совпадает с `memory.json`.

Ответы `FakeListChatModel` заданы заранее: демонстрация проверяет интеграцию цепочек,
памяти и настоящих локальных функций, а не качество LLM. Аналогично регрессионные
тесты всех шести вопросов из `1 lab/questions.md` проверяют выполнение заданных
последовательностей вызовов. Отдельный тест проверяет `ChatOpenAI` с подменённым HTTP.
Проверка настоящей модели требует запущенного API; сценарий дан в notebook.

## Ограничения

- Финансовые данные остаются учебными константами из lab 1, не рыночными данными.
- После перезапуска окно диалога и сводка начинаются заново.
- Одновременно файл должен изменять один процесс; блокировка нескольких писателей не реализована.
- Повреждённый JSON не перезаписывается. Сбой извлечения не меняет факты;
  сбой генерации ответа не отменяет уже сохранённые сведения.
- Удаление отдельных фактов через чат не реализовано. Новый `USER_ID` создаёт новый профиль.
- `stack` и `level` оставлены как необязательные факты из задания; отдельной анкеты
  для собеседований нет, финансовые запросы не требуют заполнения всех полей.
