# LLM Practicum — Домашнее задание

## Финансовый ассистент с вызовом инструментов

Ассистент-консультант по личным финансам. Отвечает на вопросы о курсах валют, ставках по вкладам, ключевой ставке ЦБ, инфляции и налоговых ставках. Вызовы инструментов парсятся **прямо из текста ответа модели** — без нативного `function calling`, `tools calling` и `MCP`.

### Что умеет ассистент

| Вопрос пользователя | Что вызовет модель | Что вернёт функция |
|---|---|---|
| «Какой сейчас курс доллара?» | `get_exchange_rate(USD)` | `1 USD = 92.50 RUB` |
| «Сколько рублей в 250 долларах?» | `get_exchange_rate(USD)` | курс, дальше модель сама умножает |
| «Где выгоднее вклад — в Сбербанке или в Тинькофф?» | `get_deposit_rate(Сбербанк)` + `get_deposit_rate(Тинькофф)` | две ставки, модель сравнивает |
| «Какая сейчас ключевая ставка?» | `get_key_rate()` | `16.00% годовых` |
| «Какая была инфляция в 2024?» | `get_inflation(2024)` | `9.5%` |
| «Какие налоги в Германии?» | `get_tax_rate(DE)` | `45.0%` |
| «Который час?» | `get_time()` | текущее время |

**Не умеет:** давать реальные прогнозы, считать налоги за конкретного человека, обращаться в интернет. Все данные — захардкоженные константы, чтобы тестировать поведение модели, а не интеграции.

### Доступные инструменты

| Функция | Аргумент | Что возвращает |
|---|---|---|
| `get_time()` | — | текущее локальное время |
| `get_exchange_rate(currency)` | код валюты: USD, EUR, CNY, KZT, RUB | курс к рублю |
| `get_deposit_rate(bank)` | название банка: Сбербанк, ВТБ, Тинькофф, Альфа | ставка по вкладу, % годовых |
| `get_key_rate()` | — | ключевая ставка ЦБ РФ |
| `get_inflation(year)` | год: 2022–2025 | инфляция за год, % |
| `get_tax_rate(country)` | код страны: RU, US, DE | ставка налога, % |

## Запуск

### Локальная модель (llama-server)

```bash

```

```bash
llama-server -m models/llama-3.2-3b-instruct-q4_k_m.gguf --port 8081 -c 4096 -ngl 99
```

**Терминал 3** — чат:

```bash
LLM_BASE_URL=http://127.0.0.1:8080/v1 LLM_MODEL=qwen2.5-3b \
    python finance_agent.py --prompt v3 -t 0.0
```

## Как это работает

Нативный `tools` API не используется. Вместо этого:

1. В системном промпте модели описан **текстовый формат вызова** функции.
2. Модель пишет вызов прямо в теле ответа.
3. Ассистент ловит вызов регуляркой (`find_call`).
4. Вызывает соответствующую Python-функцию (`call_function`).
5. Кладёт результат обратно в диалог как сообщение `Результат имя(аргумент): ...`.
6. Повторяет шаги 2–5, пока модель не выдаст финальный ответ без вызова.
7. Максимум `MAX_STEPS = 6` итераций — защита от зацикливания.

### Форматы вызова, которые понимает парсер

В процессе отладки выяснилось, что модели не всегда следуют заданному формату — Qwen2.5 и Llama-3.2 обучены на Hermes-style tool calling и **нормализуют любой маркер** к своему привычному виду. Поэтому парсер принимает несколько вариантов:

- `$function$имя(аргумент)$function$` — заданный в промпте формат;
- `<call>имя(аргумент)</call>` — как пишет Qwen2.5 после нормализации;
- `<tool_call>...</tool_call>` — родной формат Qwen;
- `function имя(аргумент)` — родной формат Llama.

Аргумент может быть в кавычках, без кавычек или в виде `name=value` — парсер срезает лишнее.

## Промпты

Четыре версии — от «почти без инструкций» до строгого пошагового алгоритма. Эволюция промптов — это задание 4.2.

| Версия | Что описывает | Ожидаемое поведение |
|---|---|---|
| `chat` | только роль ассистента, без инструментов | модель отвечает сама, вызовов нет |
| `v1` | маркер + список функций, без примеров | слабая модель путается в формате |
| `v2` | маркер + `<format>` + пример + «не выдумывай результат» | стабильно работает на 3B |
| `v3` | пошаговый алгоритм + «вызов = отдельное сообщение» | надёжно, но избыточно для больших моделей |
